# Management & Leadership Mid-Semester Report
## Initiative: Researcher-to-Project Matchmaking 💛

### Initiative/Procedure Description
This initiative aims to improve researcher-to-project matchmaking by building on the standardized application process by systematically taking the researcher inputs that include their interests, skills, and goals, and pair them with structured input via a survey from faculty leads on historical project challenges, projected project needs, and researcher expectations. The purpose is to enable a more personalized yet efficient matching process to boost retention/enagement, while minimizing the extra lift currently placed on admins.

### Hypotheses/KPIs
1. Given a holistic view of faculty/project needs that is incorporated in the matchmaking process, there will be greater engagement from the researchers.

I will need to collect data on existing retention and engagement metrics, which I can request from the PMs based on their observations/weekly report collections.

2. Given a consolidated team-matching system, the amount of time admins spend on manual team-matching will be reduced.

I will need to collect data, if it exists, on currrent time spent and paperwork the admins do for the matchmaking process. 

### Testing Hypotheses
1. Once the engagement proxies are collected, we can compare project progress from this semester to next semester and evaluate whether retention and engagement went up as a result of the systemized process, where a randomized selection of projects can participate in this pilot.

2. From my current understanding, the matchmaking is done on an ad hoc basis between applicant interests and recruitment statuses, so these may not be captured. We may alternatively compare the next application cycle and measure how long it takes to review an application on avergae and compare with what the system would recommend, and assess how much manual admin intervention was required.
